# 🌍 Translating OfficeMatrix

OfficeMatrix speaks **English by default** and Spanish on request. Switch with the **EN | ES** selector in the top
bar or in *Getting started → ⚙ Settings*. The choice is saved in your browser and on the server, and the page does
not reload.

There are no i18n libraries here, just one JSON dictionary per language and a few lines of code.

| File | What it does |
| --- | --- |
| `public/i18n/en.json` | Every English string, flat keys: `"ui.tab.reports": "REPORTS"` |
| `public/i18n/es.json` | The same keys in Spanish |
| `public/i18n.js` | Browser side: loads the dictionary, translates the HTML, exposes `t()` and `I18N.setLang()` |
| `lib/i18n.js` | Server side: the same dictionaries for notices, failure diagnoses and briefs; saves `preferencias.json` |
| `tests/i18n.test.js` | Fails if a key is missing in a language, a placeholder differs, a key used in code does not exist, or the HTML has text with no key |

## ✍️ Adding a string

1. Add the key to **both** `en.json` and `es.json`. Use placeholders in braces for variable parts:
   `"fail.tiempo.detail": "It went over the {min} min limit per turn."`
2. Use it:
   - **HTML**: `<button data-i18n="ui.save">SAVE</button>`. Write the English text inside too; it is what you see
     before the dictionary loads. Attributes have their own markers: `data-i18n-title`, `data-i18n-placeholder`,
     `data-i18n-aria-label` and `data-i18n-hover` (the app's tooltip). Use `data-i18n-html` only for your own strings
     that carry `<b>` or `<code>`.
   - **Browser code**: `t('ui.errUi', { msg: err.message })`. If the text is painted by code, repaint it on the
     `om-lang` event (see the listener at the end of `public/app.js`).
   - **Server code**: `const { t } = require('./lib/i18n')`, then the same call.
3. Brand names and language names that never change get `translate="no"`, e.g. `<span translate="no">Grok Bots</span>`.
4. Run `npm test`.

> 💡 Compare by **meaning, not by text**. A failure has a `kind` (`saldo`, `limite`, `sesion`…) and a translated
> `label`. Code should check the `kind`, since the `label` changes with the language.

## 🗣️ The agents' protocol

Agents end each turn with a report block, in English or in Spanish. Both parse to the same values:

```
OBJECTIONS:                 OBJECIONES:
- one per line, with why    - una por línea, con su porqué
REPLIES:                    RESPUESTAS:
- #3 RESOLVED: …            - #3 RESUELTA: …
SCORE: 9/10                 NOTA: 9/10
VERDICT: APPROVED           VEREDICTO: APROBADO
DONE: YES                   TERMINADO: SÍ
```

Reply stances: `RESOLVED`, `REJECTED`, `AGREED`, `WITHDRAWN`, `MAINTAINED` (or `RESUELTA`, `RECHAZADA`, `DE ACUERDO`,
`RETIRADA`, `MANTENIDA`).

Briefs go to the agents in the app's language, unless the request itself is written in another language.
`lib/i18n.detectLang()` makes that call.

Built-in templates and workflow cards are translated when requested, so changing the server preference does not
require restarting the process. Custom templates, requests, agent reports, staff profiles and brand instructions
keep the text their author supplied. Sequential, Delphi and Council briefs use the request language, including
their protocol and quality criteria. Council accepts both `SCORES:` and `PUNTAJES:`. Handoff readers accept both
English and Spanish headings and section names.

Activity labels (`stream.*`) are translated when the CLI output is parsed, so a language change applies to the next
event. Phase names (`PHASES` in `lib/brief.js`) are read on each access, so they follow the server language without
a restart. Server notices, cycle summaries, the *Today* board and failure diagnoses use the server language.
What the agents read (the turn prompt, the handoff OfficeMatrix writes in parallel modes, bot contributions and the
"recently completed" history) follows the request language. Editorial briefs follow the brand's language (its tone,
niches and "do not publish" list). Dictionary parity checks the keys; it does not prove every source string has
moved, so stored data values (`estado: 'pendiente'`, outcome codes, folder names) stay as they are on purpose.

## ➕ Adding a language

1. Copy `public/i18n/en.json` to `public/i18n/<code>.json` and translate the values (keep the keys and `{placeholders}`).
2. Add the code to `LANGS` in `public/i18n.js`.
3. Add a button `<button type="button" data-lang="<code>" translate="no">XX</button>` to `#langSeg` and an option to
   `#langSel` in `public/index.html`.
4. `npm test`: the parity test reports every key you missed.
